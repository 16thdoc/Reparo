# Reparo 1.4.4.8

Maintenance outcomes now survive many output, presentation and later-orchestration
failures. Command exits, installed effects, evidence health and deferred finality
are separate facts, shown in a compact human panel and a manual AI repair handoff
from the same versioned ledger.

- Retain literal child-host argv, observed process identity, nullable actual exit
  and separate raw streams. Commit package receipts before a later launch fails.
- Bind user workers to the expected SID/session and non-elevated medium token;
  verify worker identity and parent creation time. Deadlines do not kill active
  installers. Read-only status can reconcile late worker receipts.
- Preserve native nonzero command outcomes, compound subcommand failures, apt
  observed version deltas and Windows Update logical phase results.
- Keep active-consumer/ownership uncertainty, npm engine/script warnings,
  restart/activation uncertainty and telemetry health visible. Ordinary updates
  do not repair profiles/npmrc, broaden trust, migrate package owners or reinstall
  PowerShell to conceal registration/channel uncertainty.
- Select validated parent maintenance evidence for status. Bound Steam manifest
  reads while retaining queue/download/completion and session protections.

Windows/native identity, Yoda quote attribution and matching text art are aligned.
The production manifest references immutable source artifacts in a separate pin
transaction. Windows/Ubuntu isolated CI passed on the reviewed implementation;
release-pin CI also validates the production manifest and isolated HTTPS install.

Compatibility: existing Windows parent exits and Ninja callback fields remain;
new structured receipts are versioned. A zero parent exit does not establish that
deferred work succeeded or installed versions changed. Native command failures
now return failure. Source-integrity controllers must explicitly review/enroll
new bytes; their guards are not bypassed by release publication.

Limits: actual multi-session token launching, comprehensive manager/channel/shim
inventories, cross-controller serialization, several installed-state adapters,
detailed apt phasing reasons and full application/service restart attribution
still require scoped acceptance. Installed changes must be observed independently;
success markers or advertised targets alone are not confirmed version upgrades.

Release publication is separate from endpoint installation and maintenance pilots.
Retain the previous 1.4.4.7 runner/manifest and endpoint configuration for reviewed
rollback. Runner rollback does not undo package, OS or download changes. See the
[reliability contract](reliability-contract.md) and
[pilot/rollback gates](review-pilot.md).
